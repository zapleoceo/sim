# Админка SIM (frontend)

Русскоязычная админка `https://sim.zapleo.com`: диалоги, клиенты, воронка, аналитика, активность,
персонажи с пробным чатом, промпты, стратегии, симуляции, каналы, контент, партнёр, администраторы, студия.
Контракт API не менялся: [api.md](api.md).

## Стек и почему

| Слой | Выбор | Зачем |
|---|---|---|
| UI-фреймворк | React 19 + TypeScript (strict) | мейнстрим, большой выбор готовых компонентов и людей |
| Сборка | Vite 7 | быстрый dev-сервер и сборка, ленивые чанки страниц |
| Компоненты | shadcn/ui (Radix UI + Tailwind CSS 4) | доступные примитивы (диалоги, меню, select, tooltip) без самописной вёрстки; код компонентов лежит в репозитории (`src/components/ui`) и правится как свой |
| Данные | TanStack Query | кеш, опрос (inbox раз в 5 с), повтор при сетевых ошибках, единая обработка загрузки/ошибок |
| Маршруты | TanStack Router | типизированные пути и search-параметры (`?d=`, `?tab=llm`, `?channel_id=`), guard'ы ролей |
| Таблицы | TanStack Table | клиенты и администраторы; серверная пагинация |
| Формы | react-hook-form + zod | схемы валидации тестируются отдельно от экрана |
| Графики | Recharts | только на странице аналитики (ленивый чанк) |
| Перетаскивание | dnd-kit | воронка; есть доступная альтернатива — меню «Переместить» |
| Иконки, шрифт | lucide-react, Inter (локально, без Google Fonts) | меньше внешних запросов |

Почему не остались на Angular: прежняя админка держалась на собственной вёрстке поверх
Angular Material (свои шелл, фильтр-бар, адаптивность), что и ощущалось «велосипедом».
У Angular нет столь же распространённого набора готовых admin-компонентов уровня shadcn/ui,
а миграция на него всё равно означала переписать все шаблоны.

## Структура `frontend/`

```
src/
  main.tsx, app.tsx, router.tsx, wiring.ts   — вход, провайдеры, маршруты, связка HTTP ↔ сессия/роутер/тосты
  lib/        — типы API (models.ts), HTTP-клиент, API по доменам (lib/api/*), сессия (auth.ts),
                ключи запросов (query.ts), тема, навигация, форматтеры, этапы воронки
  components/ — общие компоненты приложения; components/ui — shadcn/ui
  layouts/    — шелл: сайдбар (сворачивается), на телефоне нижняя панель + «Ещё»
  features/<экран>/ — страница, её чистая логика (*-logic.ts, *-schema.ts) и тесты
  test/       — setup, фейковый backend (fakeApi), рендер всего приложения (renderApp)
```

## Сессия и безопасность (как раньше)

- Вход только через Telegram Login Widget (`/api/auth/telegram`); 403 показывает Telegram ID
  с кнопкой копирования.
- Cookie-сессия (`credentials: include`), `X-CSRF-Token` на POST/PUT/PATCH/DELETE.
- 401 на любом запросе → `/login?returnUrl=…` (кроме самого входа); `returnUrl` принимается
  только как путь этого же приложения.
- Остальные ошибки → один понятный тост по статусу (`lib/errors.ts`); сырой текст backend
  в тост не выводится, подробности — в console. Фоновые опросы и экраны со своей
  обработкой ошибок вызывают API с `silent`.
- Роли: operator видит рабочие разделы; owner и superadmin — также настройки;
  «Администраторы» — только superadmin. Владелец по `/` попадает в «Студию», оператор — в «Диалоги».
- Пробный чат персонажа больше не глотает ошибки: сообщение остаётся, рядом видна ошибка
  и кнопка «Повторить».
- В пробном чате можно записать голосовое (кнопка микрофона, `MediaRecorder`: WebM/Opus, в Safari MP4)
  и прикрепить файл (скрепка: аудио, изображение, текстовый файл). Сначала Broker превращает его в текст
  (`POST /api/personas/{id}/preview/attachment`, пока идёт распознавание, виден «распознаю…»), затем
  текст уходит персоне как обычное сообщение; у сообщения виден плеер или картинка и распознанный текст.
  Если персона говорит голосом (режим «всегда» или «зеркально» на голосовое), под ответом плеер с её
  голосовым; ошибка синтеза показывается, текст ответа остаётся. Логика: `features/personas/preview-chat.ts`,
  запись: `use-voice-recorder.ts`.
- У персонажа нет `disclosure_text`, у стратегии нет «Задержки ответа» (`reply_delay_s`): оба поля
  удалены из API (PR #20, миграция 0009). Все поля открыты сразу, без «Дополнительно». В редакторе персонажа только имя, модель, стратегия, аватар, описание (личность и легенда) и голос: возраст, пол, язык и «Чего нельзя» не редактируются (сохранённые значения не теряются, пустые язык и пол становятся ru и female), ограничения настраиваются в симуляторе.
- Стратегия на одном экране из трёх блоков: «Что продаём» (название, партнёр, ссылка, оффер), «Как вести
  разговор» (один текст сценария) и «Напоминания» (в днях); цель, подсказки по этапам и правила не
  редактируются (склеены в сценарий миграцией 0012).
- «Дата рождения» и «Часовой пояс» персонажа: возраст, знак зодиака и местное время считает код.
- Промпт персонажа одно поле «Промпт персонажа» (`description`): весь её промпт одним текстом (кто она,
  легенда, роль, стиль, что можно и нельзя). Под ним «Полный промпт, который получает модель»
  (`GET /api/personas/{id}/prompt`, грузится по нажатию): её текст, стратегия и формат ответа.
- «Общие правила» (`/settings`, owner): служебные промпты («Формат ответа персонажа», «Повтор при неверном
  ответе») и параметры из `/api/settings`, кроме групп агентов («Охранник», «Паспортистка»), сгруппированы по `group`, каждое поле
  открыто, у каждого «Сохранить» и «Вернуть по умолчанию».
- «Агенты» (`/agents`, owner; старый адрес `/guard` ведёт сюда): у каждого агента своя карточка с моделью и
  инструкцией. «Паспортистка»: «Модель» (`passport_model`) и «Инструкция паспортистки» (`passport_prompt`),
  она ведёт паспорт каждого лида. «Охранник»: два поля, «Модель» (выбор из моделей Broker, как у персонажа; пусто: решает
  маршрут) и «Промпт охранника» (`guard_prompt`, весь его промпт одним текстом). Ниже с замком
  контракт согласованности управляющих полей (`fixed.guard` из `/api/settings`). Маршруты Broker
  (`guard_capability`, `guard_fallback_capability`) на странице не показываются: это запасной путь,
  меняется через API.

- Карточка клиента (`/clients/$id`): спокойная, только нужное. Сверху имя (карандаш для переименования),
  строка «этап · статус · последний контакт» и кнопка «Открыть диалог» по каждому каналу. Слева переписка
  пузырями, как в «Диалогах» (общий `components/message-bubble.tsx`), без фильтров и технических данных
  (модель, токены, стоимость смотрятся в «Активности»): последние 30 сообщений, «Показать раньше» догружает
  ещё. Справа одна панель: «Этап и статус» (два списка), «Следующий шаг» и «Когда», потребности, «Заметки»;
  поля сохраняются сами при уходе с поля (Enter в однострочном), без кнопки «Сохранить». «Паспорт собеседника»
  и «История» свёрнуты. Переписка и этап обновляются живыми событиями (`lib/live.ts`).

## Адаптивность и скорость

- От 360 px: на телефоне нижняя панель с первыми разделами и «Ещё»; фильтры открываются
  снизу; inbox показывает либо список, либо переписку (до 1024 px); карточка клиента
  справа в inbox — от 1280 px.
- Светлая, тёмная и системная темы (меню пользователя), без вспышки при загрузке.
- Каждая страница — отдельный чанк; React и TanStack вынесены в долгоживущие чанки.

## Сборка, тесты, деплой

Только в CI (`.github/workflows/ci.yml`, job `frontend`), локальные прогоны запрещены AGENTS.md:
`npm ci` → `npm run lint` → `npm run typecheck` → `npm test` (Vitest + Testing Library, jsdom) →
`npm run build`. Сборка кладётся в `frontend/dist/sim/browser` — этот путь читают backend
(`SIM_STATIC_DIR`, SPA-fallback на `index.html`), `infra/build_release_artifact.py` и job `deploy`,
поэтому упаковка и выкладка не менялись.

Тесты лежат рядом с кодом (`*.test.ts(x)`): чистая логика экранов и схемы форм, общие
компоненты, HTTP-клиент, guard'ы и шелл, и страничные тесты, которые рендерят всё
приложение на memory-роутере с фейковым backend (`src/test/fake-api.ts`) — без сети.

Dev-сервер (если разрешён): `cd frontend && npm ci && npm run dev` → `http://localhost:4200`,
`/api` и `/hooks` проксируются на `http://localhost:8000`.

## Аналитика: расходы

Блок «Расходы» на странице «Аналитика» показывает деньги, потраченные всем проектом SIM за выбранный
период, по данным Broker (`GET /api/analytics/spend` → Broker `GET /v1/usage`): итог, сегодня и этот
месяц относительно лимитов проекта в Broker (полоса краснеет от 90%), разбивку по видам запросов
(голосовые, ответы персонажей, охранник, распознавание). SIM ничего не пересчитывает. Фильтр
персонажа к расходам не применяется. Подписки Claude и Codex оплачиваются фиксированно и в сумму не
входят. Плитка «Запросы к ИИ» считает вызовы из журнала SIM. Логика: `features/dashboard/spend-logic.ts`,
карточка `spend-card.tsx`.
