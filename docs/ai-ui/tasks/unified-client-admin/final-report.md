# Единая переписка и администрирование SIM

Рабочая ветка: `codex/unified-client-admin`, база main `349dc66`.
Изменения реализованы локально; production не изменялся.

## Результат

- Карточка клиента объединяет сообщения всех связанных диалогов. У каждой записи
  видны канал/аккаунт, автор, время и доступные модель/провайдер/токены/стоимость.
  Новые ручные ответы сохраняют имя оператора на момент ответа.
- Раздел «Активность» показывает сообщения со связанными фильтрами и страницами.
  Владелец и суперадминистратор также видят отдельные вызовы ИИ с результатом,
  задержкой, кешированными токенами и расходом. Оператор не запрашивает этот API.
- Ссылки из каналов и диалогов ведут в нужный контекст. Ответ отправляется через
  конкретный диалог. Формы клиента, воронка и история остаются перед длинной лентой;
  кнопка в карточке прокручивает сразу к переписке.
- Общие компоненты текста/медиа/метаданных заменяют дублирование. Запросы истории
  вынесены в отдельный репозиторий: SQL-фильтры/count/limit/offset, общий разбор дат,
  индексы порядка сообщений, строгие frontend-типы и отмена устаревших запросов.
- Миграция0008 добавляет nullable автора и индексы. Исторические неизвестные значения
  не выдумываются; время отправки берётся только из подтверждённой квитанции.
  Защита от повторной отправки из PR12 сохранена.

## Проверки

- Backend: **572 passed**, один существующий тест не может создать symlink в Windows
  (WinError1314), 24 предупреждения Alembic. Полный прогон имеет exit1, не объявляется
  полностью зелёным. Новый тест миграции первоначально нарушал изоляцию логирования;
  исправлен, проверен отдельно и в полном повторном прогоне.
- Frontend: **91/91 ChromeHeadless tests**, production build, ESLint, spec typecheck — PASS.
- Ruff — PASS. Пять затронутых backend-модулей проходят mypy; полный проект сохраняет
  **18 прежних ошибок типизации в шести файлах**.
- Проверены совместные фильтры, пагинация/count, даты/UTC, роли, изоляция клиентов,
  безопасные ошибки, nullable/zero метрики, снимок автора и SQLite migration roundtrip.
- Визуальная проверка: **12 ширин, 132 проверки размеров, 0 ошибок**; реальные переходы,
  совместные фильтры, страницы, пустые состояния и роли проверены в Chrome. Исправлены
  три обнаруженные проблемы мобильной компоновки/перехода. Детали независимых gate:
  `visual-validation.md` и `quality-review.md`.
  Локальный стенд содержит синтетические данные, пустой реестр коннекторов и не запускает worker.

## Границы и следующий шаг

Это рефакторинг модулей переписки/активности и их интеграции в существующую админку,
а не переписывание всех остальных сервисов. Остальной архитектурный долг из аудита,
включая полную типизацию, остаётся отдельной работой.

Журнал содержит сохранённые сообщения и отдельные вызовы ИИ, не все HTTP-запросы и
изменения настроек. Люди с одинаковыми именами не объединяются автоматически;
коннектор должен связывать правильный существующий `client_id` в пределах персонажа.
Offset-страницы не являются снимком при параллельных вставках; substring/count стоимость
нужно проверить на целевых production-объёмах. PostgreSQL migration/load и реальные каналы
не проверены этим локальным стендом.

Перед релизом нужны отдельная авторизация выкладки, проверка миграций на PostgreSQL,
backup/restore и затем проверка каждого реального подключаемого канала. Локальный
интерфейс не доказывает доставку внешним транспортом.

Руководство: [admin-activity.md](../../../admin-activity.md).
Детальные проверки: `backend-validation.md`, `functional-validation.md`, `frontend-validation.md`.
