# Звонки: живой голос персонажа

Код: `backend/sim/telegram/calls/`. Тесты: `backend/tests/telegram/test_calls.py`,
`test_call_audio.py`. Контекст звонка — [context.md §5](context.md). Её собственные звонки и
запланированные менеджером — [initiative.md](initiative.md).

Входящий личный звонок в Telegram принимает персонаж: звук идёт в живую голосовую модель
через Broker (`LivePort`, `/v1/live`), её речь — обратно в звонок. Всё происходит в процессе
`telegram`, на том же клиенте Telethon, что и переписка (одну сессию нельзя подключать
дважды). Звонит она и сама (`call.direction = out`): по своему решению в ходе ответа
(«давай созвонимся») или по плану менеджера — см. «Её звонок» ниже и
[initiative.md](initiative.md).

## Части

| Модуль | Что делает |
|---|---|
| `backend.py` | Протоколы `IncomingCall`, `OutgoingCall` (`ring` → `NoAnswer`) и `CallBackend` (`start`, `dial`): что сервис звонков ждёт от транспорта. Подменяется фейком в тестах |
| `pytgcalls_backend.py` | Реализация на py-tgcalls 3 / ntgcalls (перенесена из v1, где работает в проде): звонок, кадры PCM туда и обратно, ответ с ограничением по времени |
| `pcm.py` | PCM 16 бит моно: пересчёт частоты, буфер кадров по 10 мс |
| `bridge.py` | `AudioBridge` — сам разговор и расшифровка |
| `tempo.py` | Скорость её речи: `atempo` в ffmpeg на каждый ход модели |
| `recording.py` | `CallRecorder` — запись разговора по времени, стерео |
| `service.py` | `CallService` — правила, порядок шагов, запись `call` и события |
| `__init__.py` | `CallsAttacher` — крючок рантайма: ставит py-tgcalls на каждый подключённый аккаунт; `dial` — её звонок через аккаунт чата (задача `telegram:place_call`) |

Если py-tgcalls не запустился (нет нативной библиотеки, аккаунт не может звонить), звонки
этого аккаунта выключаются, переписка продолжает работать. При `SIM_CALLS_ENABLED=false`
py-tgcalls вообще не подключается: звонки звонят на других устройствах аккаунта и не
записываются.

## Ход звонка

```
звонок → Inbox.resolve_chat (клиент и чат, при необходимости создаются)
  → строка call (ringing) → можно ли брать трубку?
      нет → отклонить; call = declined, причина в error; событие call
  → контекст звонка (ContextBuilder.for_call)        сбой → failed, отклонить
  → пауза «звонок идёт» SIM_CALL_RING_MIN_S…MAX_S (случайно, 3–7 с)
      звонящий сбросил → missed
  → открыть сессию Broker live (ДО ответа)            отказ → failed, отклонить
  → ответить                                           звонящий ушёл → missed; сбой → failed
  → call = active, started_at
  → разговор (AudioBridge) до конца
  → закрыть сессию Broker, положить трубку
  → call = ended: длительность, расшифровка, стоимость, модель, ошибка; событие call
  → deps.tasks.refresh_memory(chat_id) (сжать начало дня, если он перестал влезать в бюджет)
  → она говорила в звонке: событие с after_call и ход ответа через 15–45 с («После звонка»)
  → запись разговора: стерео OGG в хранилище («Запись звонка»)
```

Сессия Broker открывается до ответа: если Broker отказал, никто «не взял трубку и не
молчит». Пока идёт звонок, транзакция БД не открыта; запись — короткими транзакциями
до и после.

### Когда она берёт трубку

Проверки по порядку, первая сработавшая — причина отказа:

1. `SIM_CALLS_ENABLED` включён;
2. пускает «шлюз ИИ» — то же правило, что для сообщений (`sim/domain/ai_gate.py`,
   [reply.md](reply.md), «Может ли ИИ отвечать в чате»): это персонаж чата, он не в архиве, ИИ
   включён у персонажа, у клиента (у нового клиента выключен) и в чате, и чат **не ждёт
   оператора** (раньше звонки это не проверяли); причина в `error` — `persona AI is off (or
   the persona is archived)`, `AI is off for this client`, `AI is off in this chat`, `the chat
   waits for an operator`;
3. у персонажа включены звонки (`persona.calls_enabled`);
4. у агента Звонок есть модель (`agent_config(persona, "live")`, [agents.md](agents.md)); звонок
   идёт на его ключах (по умолчанию платных, поле `key_tier` в сообщении `start`).

Потом — её жизнь и её «Внимание» ([attention.md](attention.md), «Звонки»): уровень занятости
по плану дня или распорядку после настроек владельца. `away` (спит, бегает; ночью с «не
беспокоить» — слот сна) — трубку не берут, звонок звонит до отбоя (не дольше 45 с), исход
`missed`; `partial` (занята) — она примерно через раз отклоняет, `declined`; `free` — отвечает
после паузы. «Всегда сразу» у персонажа и «Отвечать сразу» в чате — трубку берут всегда.
Не взятый звонок пишет в `error` уровень и занятие («away: сон…»), в событие `call` —
`life_busy` и `life_activity`, и (если включено «Писать после пропущенного звонка») просит
проверку телефона: когда она посмотрит, агент Внимание обычно решает написать, почему она не
ответила (`text_after_missed_call`).

### Исходы и что записано

| Статус | Когда | `error` |
|---|---|---|
| `declined` | одно из правил выше; или она занята (`partial`) | причина |
| `missed` | звонящий сбросил во время паузы или пока брали трубку; или она недоступна (`away`) | `the caller hung up first` / `away: …` |
| `failed` | не собрался контекст, Broker отказал, Telegram не дал ответить, процесс перезапустился посреди звонка | текст ошибки |
| `ended` | разговор состоялся | ошибка модели или моста, если была |

Каждый исход — строка `call` и **одно** событие `call` (`actor` — кто звонил: `client` или
`persona`; видно агенту) с `data`: `direction`, `status`, `duration_s`, `lines` (число
реплик), `error`, `end_reason`, у разговора, где она говорила, — `after_call: true`.
Сжатие начала дня ставится только после состоявшегося разговора (`ended`); в паспорт клиента
([leads.md](leads.md)) звонок попадает ночью, вместе с итогом дня ([memory.md](memory.md)).
Отвечает всегда персонаж чата (персонаж канала), архивный — не берёт трубку.

### После звонка

Живая модель в звонке ничего не делает, только говорит: обещанное там («сейчас пришлю
кружок», «перезвоню») раньше никто не выполнял, и следующая проверка телефона видела только
сообщения — клиента, с которым она только что говорила, агент Внимание принимал за
навязчивого незнакомца (чат 3, 2026-11-22). Теперь:

- событие разговора, в котором она говорила, — `after_call: true`; оно ждёт её хода, как
  сообщение клиента (`turn_state.waiting_events`), и сразу после звонка ставится ход ответа
  (15–45 с): модель ответов видит расшифровку в ленте и по правилу «Только что был звонок…»
  ([reply.md](reply.md)) делает обещанное в этом ходе — кружок, фото, текст, а «перезвоню» —
  своим звонком (`call`, если в чате «Звонит сама»), иначе пишет, когда наберёт;
- проверка телефона видит такой разговор как новость и правилом отвечает сразу («только что
  говорили по телефону»), а в последних строках чата у агента Внимание теперь и её звонки
  («звонок от Дмитрия, поговорили 1:42 — в конце: …»).

## Её звонок

`CallService.dial(contact_id)` — звонок по запланированному контакту, который минутный тик
перевёл в `started` ([initiative.md](initiative.md)):

```
контакт → можно ли звонить? (тот же шлюз ИИ; звонки на сервере и у персонажа; модель Звонка;
          мессенджер чата — Telegram; её собственная идея — ещё и «Звонит сама» в чате;
          с ним уже не идёт звонок)        нет → контакт failed «не позвонила: …», строки call нет
  → строка call (out, ringing), contact.call_id; контекст звонка с поводом (for_call(outgoing_topic))
  → аккаунт чата: dial(peer) — пользователь подтягивается в кэш Telethon по access hash
  → ring(40 с): не взял → missed, сбросил или занято → declined
        → контакт failed («не взял трубку» / «сбросил звонок» / «занято»), событие initiative
          «ты звонила ему (…), он не взял трубку — напиши коротко…» и ход ответа через 1–4 мин
  → взял: сессия Broker live (без приветствия: она ждёт его «алло» и говорит, зачем звонит)
  → разговор, как у входящего → ended; контакт done «поговорили N мин»
```

Повод звонка — в правилах живой модели (`CALL_OUT_RULES`). Перезапуск посреди звонка: строку
`call` закрывает `close_stale`, контакт — минутный тик (`started` дольше 10 мин без живого
звонка → failed).

## Запись звонка

`persona.call_recording` (по умолчанию включено) — разговор записывается: `AudioBridge` кладёт
в `CallRecorder` каждый кадр собеседника (uplink) и каждый её кадр, ушедший в звонок (pacer),
по времени от ответа — паузы и перебивания звучат как были. Запись в памяти, 16 кГц: собеседник
— левый канал, она — правый (9 минут — около 35 МБ). После того как звонок закрыт,
`MediaToolsPort.call_recording` (ffmpeg) делает стерео OGG/Opus 32 кбит/с (около 2,5 МБ за 10
минут), файл ложится в хранилище медиа (`calls/…`), в `call.recording_key` и `recording_s`.
Сбой записи теряет только звук: звонок, расшифровка и событие уже записаны. Слушать — в ленте
чата у звонка (`GET /api/calls/{id}/recording`, с Range).

Срок — `persona.call_recording_days` (по умолчанию 90): раз в час `agent.recordings_tick`
(`sim/services/recordings.py`) удаляет записи старше; кнопка «Удалить старые записи» на
странице персонажа делает то же сразу (`POST /api/personas/{id}/call-recordings/purge`,
`{days}`: `null` — её срок, `0` — все записи). Удаляется только звук; файлы стираются
после коммита, так что звонок никогда не ссылается на пропавший файл.

Собеседник о записи не предупреждается: для настоящих клиентов в некоторых странах нужно
согласие — тогда запись выключают у персонажа.

## Скорость речи

`persona.voice_speed` (0.8–1.5, по умолчанию 1.0; поле «Скорость речи» в разделе «Голос»).
У живой модели нет настройки скорости, но её звук приходит быстрее реального времени, поэтому
речь растягивается на выходе: `tempo.FfmpegTempo` — один ffmpeg на ход модели (24 кГц
s16le → `atempo`, тон не меняется → 48 кГц в буфер звонка). Конец хода (`turn_complete`)
закрывает вход и дожидается хвоста; `interrupted` убивает процесс — после того как её
перебили, ничего не доигрывается. Если ffmpeg не запустился или упал, она говорит в темпе
модели (обычный пересчёт частоты): звонок из-за скорости не срывается. При 1.0 процесса нет.
Голосовые ускоряются тем же `atempo` ([persona-life.md](persona-life.md), «Звук»).

## Разговор (`AudioBridge`)

Три задачи:

- **uplink**: кадры звонящего (48 кГц) → 16 кГц → в Broker кусками по 40 мс;
- **downlink**: события модели:
  - `audio` (24 кГц) → 48 кГц → в буфер (при скорости ≠ 1 — через `Tempo`);
  - `transcript_in` / `transcript_out` → расшифровка (клиент / персонаж);
  - `interrupted` (если адаптер Broker его передаёт) → буфер очищается: её перебили;
  - `turn_complete` → хвост буфера дополняется тишиной до целого кадра;
  - `done` → модель закончила; `error` → модель упала;
- **pacer**: из буфера в звонок по кадру 10 мс в реальном времени. Расписание абсолютное:
  опоздание компенсируется следующей паузой; отставание больше 0.1 с — расписание
  начинается заново, без «очереди» кадров.

Конец разговора — что случится раньше:

| Причина (`end_reason`) | Что произошло |
|---|---|
| `hung_up` | звонящий положил трубку |
| `model_done` | модель закончила; её последние слова ещё доигрываются (до 10 с) |
| `model_error` | модель прислала ошибку (`error` = её текст) |
| `time_limit` | прошло `max_seconds` из контекста звонка (по умолчанию `SIM_CALL_MAX_SECONDS` = 540) |
| `bridge_error` | упала одна из задач моста (например, оборвался сокет) |

Распознавание языка: у живой модели нет настройки языка собеседника (Broker шлёт только
`speechConfig.languageCode` — язык её речи), и короткое «алло» в шуме ей слышалось как
португальское «Alô» — она извинялась, что не знает португальский, и предлагала выбрать язык
(2026-11-22). Правило звонка (`CALL_RULES`): собеседник говорит на языке переписки, послышалась
иностранная речь — это помехи, переспроси; о языках и «технических возможностях» не говори.

Если за весь звонок в трубку не ушло ни одного кадра — предупреждение в логе
(«the caller never heard her»).

### Расшифровка

`call.transcript = [{"who": "client"|"persona", "text": "...", "t": секунды_от_ответа}]`.

Живая модель присылает распознанную речь кусками. Подряд идущие куски одного говорящего
склеиваются в одну реплику (если кусок начинается с буквы после `.`, `!`, `?`, `…` —
через пробел), пробелы нормализуются, пустые куски отбрасываются. `t` — время первого куска
реплики. Если событий расшифровки не было, берётся расшифровка из итога Broker
(`finish()["transcript"]`, роли `user` → клиент, остальное → персонаж).

Стоимость (`cost_usd`) и модель — из итога Broker (`finish()`); модель по умолчанию — из
контекста звонка.

## Звук

PCM 16 бит, little-endian, моно. Telegram (ntgcalls) — 48 кГц, кадры по 10 мс (960 байт).
Broker: вход 16 кГц, выход 24 кГц. Пересчёт на чистом Python (`array`): кратное понижение —
среднее по группе (грубый фильтр, для речи достаточно), остальное — линейная интерполяция.
Звонок — около 100 КБ/с, это не нагружает цикл событий.

## py-tgcalls

- Ответ: `play(ExternalMedia.AUDIO, 48 кГц моно, CallConfig(timeout=20))`, затем
  `record(RecordStream)`. Если звонящий сбросил, пока ждём подтверждения, ответ отменяется
  сразу, и py-tgcalls получает `leave_call`, иначе следующий звонок этого человека ждал бы
  чужой таймаут.
- Отклонение: `leave_call` по звонку, к которому не подключались.
- Её звонок: `play(user_id, …, CallConfig(timeout=40))` — py-tgcalls запрашивает звонок и
  ждёт ответа; `TimedOutAnswer` → `NoAnswer("no_answer")`, `CallBusy` → `busy`,
  `CallDeclined` / `CallDiscarded` → `declined`. Перед этим пользователь берётся через
  `get_entity(InputPeerUser)`: после перезапуска кэш Telethon пуст.
- Кадры звонящего — из обновлений `StreamFrames` (направление «входящее», микрофон).
- Конец звонка с той стороны — `DISCARDED_CALL`, `LEFT_CALL`, `BUSY_CALL`.
- Повторный звонок того же человека, пока старый дозавершается, — отдельный звонок: старый
  забывает только свою запись.
- Звонок «своего» аккаунта ищет имя звонящего в кэше Telethon (`get_entity`); если не
  нашлось, звонок всё равно обрабатывается по id.
