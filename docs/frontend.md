# Дашборд (фронтенд)

React 19 + Vite + TypeScript, TanStack Router/Query/Table, react-hook-form + zod, Radix UI
(компоненты в стиле shadcn/ui) и Tailwind 4. Интерфейс на русском. Контракт с бэкендом —
`docs/api.md`, другие ручки фронт не вызывает.

Сборка кладёт файлы в `frontend/dist/sim/browser` — оттуда их отдаёт бэкенд и берёт `deploy`.
Проверки (`npm run lint`, `typecheck`, `test`, `build`) запускаются только в CI.

## Структура

```
frontend/src/
  main.tsx, app.tsx      вход: QueryClient, роутер, тема, тосты, обработчик 401
  router.tsx             маршруты: /login, /chats(?id=), /personas, /personas/$personaId,
                         /leads(?persona=&stage=), /leads/$clientId; старые /persona и
                         /clients… перенаправляются
  layouts/app-shell.tsx  слева три раздела (Чаты, Персонажи, Лиды), на телефоне — нижние вкладки;
                         здесь же открывается поток живых обновлений
  lib/api.ts             единственная обёртка над fetch
  lib/query.ts           QueryClient и реестр ключей `qk`
  lib/events.ts          SSE `/api/events` → какие запросы перечитать
  lib/types.ts           типы ответов API
  lib/format.ts          даты, длительности, деньги
  components/ui/*        кит (button, input, select, sheet, dialog, switch, table, tabs, …)
  components/*           общие блоки: Field/Section, DataTable, EmptyState, Confirm, Page
  hooks/*                media query, debounce, «несохранённые изменения», бесконечная прокрутка
  features/auth          вход через Telegram Login Widget, сессия и CSRF
  features/chats         список, переписка, «Почему так», отправка от оператора
  features/persona       список персонажей, страница персонажа (форма, фильтр моделей, медиатека),
                         «Клонировать», «Канал» (вход в Telegram по QR); persona-scope.tsx —
                         id открытого персонажа для жизни, медиатеки и канала
  features/persona/life  «Жизнь»: день, мир (распорядок, люди, увлечения, места), истории, канон
  features/leads         «Лиды»: таблица с фильтрами, карточка лида, паспорт (правка и замки),
                         короткий паспорт для шапки переписки
  test/*                 фейковый бэкенд (`fakeApi`), рендер с провайдерами
```

У каждой фичи свой `api.ts` (тонкие функции над `lib/api.ts`), чистая логика лежит в
`*-logic.ts` / `model-filter.ts` и покрыта тестами отдельно от компонентов.

## HTTP

`lib/api.ts`: путь относительно `/api`, `credentials: 'include'` (cookie `sim_session`),
заголовок `X-CSRF-Token` на каждом не-GET запросе. Токен приходит из `/auth/me` или
`/auth/telegram` и хранится в памяти (`features/auth/session.ts`). Ответ с ошибкой
`{"error": "текст"}` превращается в `ApiError` с этим текстом; без `error` — понятный текст
по коду. 401 сбрасывает сессию и кэш и ведёт на `/login?returnUrl=…`.

Ошибку любой мутации показывает один общий тост (`MutationCache` в `lib/query.ts`), успех —
тост в самой фиче. Ошибки чтения показываются на месте с кнопкой «Повторить».

## Где какая настройка

Каждая настройка редактируется ровно в одном месте.

«Персонаж» ниже — страница одного персонажа (`/personas/$id`), все её запросы идут под
`/personas/{id}` (сокращённо `…`).

| Настройка | Где | Запрос |
|---|---|---|
| Новый персонаж | Персонажи → «Клонировать» в строке или в шапке страницы персонажа (один диалог `CloneDialog`) | `POST …/clone` |
| Архив / вернуть | Персонаж → шапка, «В архив» / «Вернуть из архива» | `PATCH …` `{is_active}` |
| Имя, пол, язык, часовой пояс, дата рождения персонажа | Персонаж → Основное | `PUT …` |
| Промт | Персонаж → Промт | `PUT …` |
| Внешность (описание для фото и видео), «Описать по референсам» | Персонаж → Внешность | `PUT …`, `POST …/appearance/describe` |
| Модели по назначениям (ответы, проверка, распознавание, расшифровка, сводка, паспорт клиента, TTS, фото, видео, звонки, жизнь — план дня) | Персонаж → Модели | `PUT …` |
| Голос, манера речи, фон в голосовых | Персонаж → Голос | `PUT …` |
| Распорядок, люди, увлечения, места | Персонаж → Жизнь → Мир (одна кнопка «Сохранить мир») | `PUT …/life` |
| Истории | Персонаж → Жизнь → Истории | `…/arcs` |
| День сегодня и завтра: правка, «Спланировать заново» | Персонаж → Жизнь → День | `…/days` |
| Канон: правка, отклонить, вернуть | Персонаж → Жизнь → Канон | `…/canon` |
| Правила проверки | Персонаж → Проверка | `PUT …` |
| ИИ / голосовые / фото / видео / звонки персонажа, пауза перед ответом | Персонаж → Переключатели (в списке «Персонажи» — только состояние) | `PUT …` |
| Правила формата ответа | Персонаж → Правила формата (только чтение, константа в коде) | `GET /instructions` |
| Канал Telegram: подключить по QR, отключить | Персонаж → Канал | `…/channels…` |
| Фото и видео, подписи, теги, «референс внешности» | Персонаж → Медиатека | `…/media`, `/media/{id}` |
| ИИ для клиента | Лиды: переключатель в строке таблицы и в шапке карточки — это один компонент `ClientAiSwitch` и одно поле `client.ai_enabled` | `PATCH /clients/{id}` |
| Имя в списках, телефон, заметки клиента | Карточка лида → Профиль | `PATCH /clients/{id}` |
| Паспорт: текст, имя, возраст, пол, город, страна, часовой пояс клиента, занятие, стадия, теплота, следующий шаг, замки | Карточка лида → Паспорт (в шапке переписки — только просмотр) | `PATCH /clients/{id}` `{passport}` |
| ИИ в конкретном чате | Чаты → шапка переписки | `POST /chats/{id}/ai` |
| «Нужен оператор» снять | Чаты → шапка, «Оператор разобрался» | `POST /chats/{id}/operator-done` |
| Заметка для агента | Чаты → шапка, «Заметка» | `POST /chats/{id}/notes` |

Персонаж отвечает в чате, только если он не в архиве и включены три переключателя: у
персонажа, у клиента и в чате. В списке чатов зелёная точка — ИИ включён и у клиента, и в чате.

Форма персонажа одна, с одной кнопкой «Сохранить» внизу экрана. Отправляются только
изменённые поля. Уйти со страницы с несохранёнными изменениями нельзя без подтверждения
(`hooks/use-unsaved-guard.ts`), так же работают профиль и паспорт лида.

## Персонажи ([personas.md](personas.md))

- «Персонажи» — таблица на всю ширину: персонаж (аватар, имя, «в архиве»), канал (аккаунт и
  статус), лиды (ссылка на «Лиды» с фильтром), ИИ, «Клонировать».
- Страница персонажа: всё, что было на странице «Персонаж», плюс шапка с «Клонировать» и
  архивом. Жизнь, медиатека и канал берут id персонажа из `PersonaIdProvider`; при переходе к
  другому персонажу содержимое монтируется заново (черновики не перетекают).
- Диалог «Клонировать» (`clone-dialog.tsx`, логика — `clone-logic.ts`): имя и галочки частей
  с подсказками, канон по умолчанию выключен, имя проверяется до запроса; после создания —
  переход на страницу клона.
- «Канал» (`channel-section.tsx`, логика — `channel-logic.ts`): «Подключить Telegram» → форма
  api_id, api_hash (поле пароля), прокси → картинка QR, перечитывается раз в 2 с, пока не
  отсканируют (новый QR приходит сам) → если у аккаунта облачный пароль — поле пароля → «Аккаунт
  подключён», список каналов перечитывается. Ошибка — текст и «Попробовать снова»; «Отменить
  подключение» закрывает вход на сервере. У подключённого канала «Отключить» (с подтверждением).

## Лиды ([leads.md](leads.md))

- «Лиды» — таблица на всю ширину: имя и username, персонаж, стадия (цветной значок), теплота,
  город, возраст, последний контакт, сообщений, ИИ; фильтры «Персонаж» и «Стадия», поиск.
  На телефоне остаются имя, стадия и ИИ.
- Карточка лида: слева паспорт (`passport-editor.tsx`): значок стадии, теплота, когда обновлён,
  поля и текст; сохраняются только изменённые; у поля, которое правил оператор, — замок
  «вручную», нажатие снимает его. Справа профиль (имя в списках, телефон, заметки) и чаты лида
  с именем персонажа.
- В шапке переписки — кто отвечает («отвечает Оля») и кнопка «Паспорт»: боковая панель с
  коротким паспортом и ссылкой на карточку.

### Фильтр моделей

`features/persona/model-filter.ts`, по `input_modalities`, `output_modalities` и
`capabilities` из `GET /models`:

| Назначение | Условие |
|---|---|
| Ответы, проверка, сводка, паспорт клиента, жизнь (план дня) | вход text и выход text |
| Распознавание | вход image или video |
| Расшифровка | вход audio и выход text |
| Голос (TTS) | выход audio |
| Фото | выход image |
| Видео | выход video |
| Звонки | capability `live` или audio на входе и выходе |

Доступные модели идут первыми, у остальных пометка «недоступна» или «доступность
неизвестна». Сохранённое значение остаётся в списке, даже если модель больше не подходит
или пропала из каталога, — сохранение формы его не потеряет.

### Жизнь

`features/persona/life` ([persona-life.md](persona-life.md)), раздел «Жизнь» на странице
персонажа, вкладки (содержимое вкладок не размонтируется — черновики не теряются):

- **День** — карточки «Сегодня» и «Завтра» (`GET /persona/days`): события с временем, местом,
  людьми, одеждой и подробностями, текущее событие выделено и помечено «сейчас» (по
  `now_minute` от сервера), значок «план модели / изменён вручную / ошибка плана / не
  спланирован». «Спланировать заново» ставит задачу (202) и потом 2 минуты перечитывает дни
  каждые 4 с. «Изменить» — таблица событий с проверкой порядка и наложений до отправки.
- **Мир** — вкладки Распорядок (дни — кнопки пн…вс, время, что, где, с кем, занятость), Люди,
  Увлечения, Места; одна кнопка «Сохранить мир» и «Отменить».
- **Истории** — карточки с названием, статусом, датой конца, сутью и стадией, своя кнопка
  «Сохранить» и «Удалить» (с подтверждением); внизу «Добавить историю».
- **Канон** — факты с датой и чатом: изменить, отклонить, вернуть.

Таблицы — общий `RowsEditor` (`rows-editor.tsx`): от 768 px сетка с заголовком, на телефоне
карточки с подписями полей. Чистая логика (проверки, дни недели, текущее событие) —
`life-logic.ts`. «Несохранённые изменения» охраняют мир и правку дня.

## Чаты

- От 1024 px два столбца: список и переписка. Уже — один: открытый чат в адресе
  (`/chats?id=5`), кнопка «назад» возвращает к списку.
- Список: поиск, фильтр «Персонаж» (если персонажей больше одного; тогда в каждой строке и имя
  персонажа, который отвечает), непрочитанные, «нужен оператор», точка ИИ, превью последнего сообщения и
  время; подгрузка следующих страниц по `before=<last_message_at>`.
- Переписка — лента `GET /chats/{id}/timeline`, старые страницы подгружаются при прокрутке
  вверх по `before_id`. Контейнер `flex-col-reverse`: лента открывается внизу и не прыгает,
  когда сверху дорисовываются старые события.
- Как рисуется событие (`timeline-entry.tsx`, `timeline-logic.ts`): сообщения — пузыри
  (клиент слева, персонаж справа, оператор справа с подписью «оператор»); фото, видео
  (`<video controls>`), голосовое (`<audio controls>` и расшифровка), файл (чип и выжимка);
  звонок — карточка с направлением, длительностью, исходом и расшифровкой; генерация —
  чип со статусом; не доставлено — красным; журнал (проверка заблокировала, нужен оператор,
  ИИ включён/выключен, заметка, память обновлена) — мелкой серой строкой по центру;
  `media_understood` отдельно не показывается.
- «Почему так» у ответа персонажа с `reply_run_id` открывает боковую панель из
  `GET /reply-runs/{id}`: блоки контекста (факты, распорядок, точные данные на сейчас,
  истории, канон, карточка клиента, сводка, лента, каталог
  медиа), план, вердикты проверки и каждый вызов модели (модель, токены, стоимость, время,
  запрос и ответ).
- Открытый чат с непрочитанными отмечается прочитанным (`POST /chats/{id}/read`).

## Живые обновления

`AppShell` один раз открывает `EventSource('/api/events')`. Каждое событие
`{chat_id, event_id, kind}` превращается в набор ключей (`invalidationsFor` в
`lib/events.ts`), и TanStack Query перечитывает только их:

| Событие | Что перечитывается |
|---|---|
| любое | лента этого чата `qk.timeline(chat_id)` |
| `message_in` | + списки чатов, шапка этого чата, клиенты |
| `message_out`, `message_edited`, `message_deleted`, `send_failed`, `call`, `guard_blocked`, `operator_needed` | + списки чатов, шапка этого чата |
| `ai_toggled` | + списки чатов, шапка этого чата, клиенты |
| `client_updated`, `memory_updated` | + клиенты |
| `media_understood`, `generation_*`, `operator_note` | только лента |

После обрыва браузер переподключается сам. Свои действия (отправка, переключатели, заметки)
тоже инвалидируют нужные ключи сразу, не дожидаясь события.

## Вёрстка

Проверяется на 1920 px и 375 px: таблицы и разделы на всю ширину, без горизонтальной
прокрутки страницы (лишние колонки таблицы клиентов на телефоне скрываются), нижние вкладки
на телефоне, переписка занимает видимую высоту экрана и не уезжает под клавиатуру
(`hooks/use-viewport-vars.ts`). Светлая и тёмная тема — в меню аккаунта.
