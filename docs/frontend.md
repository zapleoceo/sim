# Дашборд (фронтенд)

React 19 + Vite + TypeScript, TanStack Router/Query/Table, react-hook-form + zod, Radix UI
(компоненты в стиле shadcn/ui) и Tailwind 4. Интерфейс на русском. Контракт с бэкендом —
`docs/api.md`, другие ручки фронт не вызывает.

Сборка кладёт файлы в `frontend/dist/sim/browser` — оттуда их отдаёт бэкенд и берёт `deploy`.
Проверки (`npm run lint`, `typecheck`, `test`, `build`) запускаются только в CI.

У каждой фичи свой `api.ts` (тонкие функции над `lib/api.ts`), чистая логика лежит в
`*-logic.ts` / `model-filter.ts` и покрыта тестами отдельно от компонентов.

## HTTP

`lib/api.ts`: путь относительно `/api`, `credentials: 'include'` (cookie `sim_session`),
заголовок `X-CSRF-Token` на каждом не-GET запросе. Токен приходит из `/auth/me` или
`/auth/telegram` и хранится в памяти (`features/auth/session.ts`). Ответ с ошибкой
`{"error": "текст"}` превращается в `ApiError` с этим текстом; без `error` — понятный текст
по коду. 401 сбрасывает сессию и кэш и ведёт на `/login?returnUrl=…`.

Ошибку любой мутации показывает один общий тост (`MutationCache` в `lib/query.ts`), успех —
тост в самой фиче. Ошибки чтения показываются на месте с кнопкой «Повторить».

Каждая настройка редактируется ровно в одном месте.

«Персонаж» ниже — страница одного персонажа (`/personas/$id`), все её запросы идут под
`/personas/{id}` (сокращённо `…`).

Персонаж отвечает в чате, только если он не в архиве и включены три переключателя: у
персонажа, у клиента и в чате. В списке чатов зелёная точка — ИИ включён и у клиента, и в чате.

Форма персонажа одна, с одной кнопкой «Сохранить» в полосе, которая прилипает к низу экрана,
пока видна сама форма (разделы ниже — Агенты, Жизнь, Канал, Медиатека — сохраняются своими
кнопками, и полоса говорит только о форме: «Настройки персонажа сохранены» / «…изменены, не
сохранены»). Отправляются только изменённые поля.

Раздел «Голос» формы:

- выбор голоса (`voice-picker.tsx`, логика — `voice-picker-logic.ts`): над списком всегда
  строка «Выбран: Kore — уверенный, женский» (сохранённый голос, которого нет в списке, — его id);
  фильтр «Все / Женские / Мужские» и поиск по id, имени и тону (без учёта регистра); список с
  прокруткой, клик по строке выбирает голос (`role="radio"`), ▶ проигрывает образец
  `GET /voices/{id}/sample?persona_id=…` (`api.blob`, та же сессия и тот же разбор `{error}`).
  Первая озвучка идёт несколько секунд — на кнопке крутилка, ошибка — строкой под голосом
  («Не удалось озвучить: …»). Играет один общий `<audio>` (`use-voice-sample.ts`): новый образец
  останавливает прежний, ■ — стоп; полученный образец не запрашивается повторно, пока открыта
  страница. Образец играет со скоростью речи персонажа без изменения тона (`playbackRate`,
  `preservesPitch`);
- «Скорость речи» — ползунок 0.8–1.5 с шагом 0.05 и значением «×1.30» (`voice_speed`,
  сохраняется со всей формой);
- манера речи и «Фон в голосовых»;
- запись звонков ([calls.md](calls.md)): «Записывать звонки» (стерео: собеседник слева, она
  справа) и «Хранить записи, дней» (1–3650, старше удаляются раз в час, расшифровка остаётся) —
  сохраняются со всей формой; «Удалить старые записи» (`call-recordings-purge.tsx`) спрашивает
  «Старше N дней» (`days: null` — по сохранённому сроку) или «Все записи» (`days: 0`) и
  показывает тост «Удалено записей: N».

Выпадающие списки (`NativeSelect`) рисует браузер; чтобы в тёмной теме их пункты читались,
`index.css` задаёт `color-scheme` по теме и цвета `select option` из токенов темы.

### Черновики и несохранённые изменения

Каждый редактор (форма персонажа, агенты, мир, истории, правка дня, канон, паспорт и «Дни» лида)
держит черновик через один хук `useDraft(serverValue, { equals?, guardName? })` (`hooks/use-draft.ts`)
→ `{ draft, setDraft, baseline, dirty, reset, commit(saved) }`:

- пока черновик не тронут, свежая копия с сервера (живое обновление, другая вкладка) сразу
  попадает в форму;
- пока оператор правит, черновик и его база (`baseline` — копия, с которой начата правка) не
  меняются; «Сохранить» отправляет разницу с базой — значения, которых оператор не трогал, не
  уходят (в паспорте отправленное поле запирается, поэтому это важно);
- «Отменить» (`reset`) возвращает самую свежую копию с сервера; после сохранения `commit(ответ
  сервера)` делает его новой базой.

Сравнение по умолчанию — `sameJson` из `lib/utils.ts` (одна функция на весь фронт).

Страница с несколькими разделами (персонаж, карточка лида) обёрнута в `UnsavedChangesProvider`
(`components/unsaved-changes.tsx`): разделы с `guardName` регистрируют себя, и при уходе со
страницы показывается один вопрос со списком: «Не сохранено: Агенты, Мир». Редактор вне такой
страницы получает свой вопрос (`hooks/use-unsaved-guard.ts`); закрытие или перезагрузка вкладки
— вопрос браузера.

## Персонажи ([personas.md](personas.md))

- «Персонажи» — таблица на всю ширину: персонаж (аватар, имя, «в архиве»), канал (аккаунт и
  статус), лиды (ссылка на «Лиды» с фильтром), ИИ, «Клонировать».
- Страница персонажа (`persona-page.tsx`): шапка с «Клонировать» и архивом, дальше разделы
  подряд — форма персонажа (`PersonaEditor`, Основное … Переключатели), Агенты, Жизнь, Канал,
  Стикеры, Медиатека; раскладывает их сама страница, у каждого раздела своё сохранение, всё вместе — в
  одном `UnsavedChangesProvider`. Агенты, жизнь, медиатека, канал и стикеры берут id персонажа из
  `PersonaIdProvider`; при переходе к другому персонажу содержимое монтируется заново (черновики
  не перетекают).
- Диалог «Клонировать» (`clone-dialog.tsx`, логика — `clone-logic.ts`): имя и галочки частей
  с подсказками, канон по умолчанию выключен, имя проверяется до запроса (и в строке списка, и
  в шапке страницы — по именам всех персонажей); после создания — переход на страницу клона.
- Список персонажей читает один хук `usePersonaList()` (`use-persona-list.ts`): таблица
  «Персонажи», фильтры «Персонаж» в чатах и лидах (один компонент `PersonaFilter`), занятые
  имена для «Клонировать».
- «Канал» (`channel-section.tsx`, логика — `channel-logic.ts`, [channels.md](channels.md)):
  список каналов (значок и название мессенджера, аккаунт, статус: «подключён», «идёт вход»,
  «нужен повторный вход», «ошибка», «выключен») и «Подключить ▾» — меню Telegram / Instagram /
  WhatsApp. Виды мессенджеров — одна типизированная таблица `CHANNEL_KINDS`
  (`channel-kinds.tsx`: вид, название, значок, форма подключения, подсказка); новый мессенджер =
  строка там. Что сервер сейчас не может подключить, меню показывает неактивным с причиной из
  `GET …/channels` (`kinds`, например «Сервис WhatsApp не запущен на сервере»). У канала со
  статусом «нужен повторный вход» или «ошибка» — «Войти заново» (та же форма), у любого не
  выключенного — «Отключить» (с подтверждением).
- Формы подключения делят шаги входа (`channel-login.tsx`: `useChannelLogin` — шаг с сервера,
  перечитывание раз в 2 с, пока `qr` или `device`, «подключён» → тост и перечитывание списков;
  `LoginShell` — ошибка с «Попробовать снова» и «Отменить подключение»; `QrStep`):
  - Telegram (`telegram-connect.tsx`): api_id, api_hash, прокси → QR → облачный пароль 2FA;
  - Instagram (`instagram-connect.tsx`): способ входа «Логин и пароль» / «Вход по sessionid» /
    «Вставить сессию JSON»; прокси обязателен (подсказка: вход с серверного IP Instagram считает
    взломом, страна прокси — страна аккаунта); потом код (из приложения-аутентификатора, SMS
    или письма), «Подтвердите вход в приложении Instagram» с ожиданием и «Я подтвердил» (сервер
    повторяет вход сам) или «Повторить» после проверки в приложении;
  - WhatsApp (`whatsapp-connect.tsx`): «Показать QR-код» → QR, перечитывается, пока телефон не
    привяжет устройство; «Отменить подключение» отвязывает его на сервере.

- «Стикеры» (`stickers-section.tsx`, группировка — `sticker-logic.ts`, [stickers.md](stickers.md)): стикеры её собственного
  аккаунта Telegram, которые сервер прочитал (установленные наборы и избранное). «Стикеров: N»,
  дальше группы — «Избранное» первым (избранный стикер только там), потом наборы по названию
  (пустое — по короткому имени) в порядке сервера; в группе — эмодзи стикеров маленькими бейджами,
  не больше 40, остальное — «ещё N». «Обновить» ставит перечитывание в очередь
  (`POST …/stickers/sync`, 202), показывает тост «Обновляю стикеры из Telegram…» и перечитывает
  список сразу и ещё раз через 5 с. Пустой список объясняет, что наборы ставят или добавляют в
  избранное в её Telegram, а Марина отправляет их сама, изредка и к месту. Здесь стикеры только
  видны — что отправить, выбирает она.
- «Медиатека» (`media-library.tsx`): загрузка (перетащить или выбрать), фильтры «Источник» и
  «Тип», сетка квадратных плиток — 2 колонки на телефоне, 3 / 4 / 5 и 6 на широком экране
  (1920 px). У видео в плитке — значок ▶ и длительность, плеера в плитке нет. Под плиткой
  подпись, теги, переключатели и «Изменить» / «Удалить». Переключатели (`ReferenceSwitches`,
  один компонент для плитки и просмотрщика): «референс лица» — у любого фото, «эталон комнаты
  «кухня»» — у сгенерированного фото комнаты её квартиры ([persona-life.md](persona-life.md),
  «Облик и дом»). Бейджи на плитке: «сгенерировано», «лицо», имя комнаты-эталона.
- Просмотрщик (`media-lightbox.tsx`, чистая логика — `media-lightbox-logic.ts`): клик по плитке
  открывает файл на весь экран (Radix Dialog: фокус внутри, Esc и «✕» закрывают). Листание —
  кнопки ‹ ›, клавиши ← → (кроме фокуса на видео, там стрелки перематывают) и свайп на телефоне
  (≥ 50 px по горизонтали, вертикальное движение — прокрутка, не листание); по кругу, «3 / 12»
  сверху. Видео играет внутри со своими кнопками. Рядом с файлом (на 1920 px — колонка справа,
  на телефоне — снизу): подпись, теги, откуда файл (сгенерировано / загружено), дата и сцена
  генерации — комната, место, занятие, одежда, свет, кадр, день (`Media.scene`). Соседние фото
  подгружаются заранее.

## Лиды ([leads.md](leads.md))

- «Лиды» — таблица на всю ширину: имя и username, персонаж, стадия (цветной значок), теплота,
  город, возраст, последний контакт, сообщений, ИИ; фильтры «Персонаж» и «Стадия», поиск.
  Фильтры и поиск живут в адресе (`/leads?q=анна&persona=2&stage=hot`): «назад» из карточки и
  присланная ссылка открывают тот же список. На телефоне остаются имя, стадия и ИИ.
- Карточка лида: слева паспорт (`passport-editor.tsx`): значок стадии, теплота, когда обновлён,
  поля и текст; сохраняются только изменённые оператором (живое обновление паспорта, пока форма

  с именем персонажа. Это вкладка «Карточка»; рядом — вкладка «Дни» (обе вкладки остаются
  смонтированными, набранный текст при переключении не теряется).

  их несколько; по каждому дню (новые сверху) — дата, кем написан итог (Летописец / изменён

- В шапке переписки — кто отвечает («отвечает Оля») и кнопка «Паспорт»: боковая панель с
  коротким паспортом и ссылкой на карточку.

### Агенты ([agents.md](agents.md))

`features/persona/agents/`: `agents-section.tsx` (раздел, черновик, одна кнопка «Сохранить
агентов», защита от ухода с несохранённым), `agent-card.tsx` (карточка агента),
`agents-logic.ts` (черновик, что отправить, итоговая модель, проверки). Реестр агентов,
группы, значения по умолчанию, промты и фильтры моделей приходят с сервера
(`GET /agents/registry`) — в дашборде их нет.

- Группы — как в реестре: Ответ, Медиа, Звонки, Фон; карточки сеткой (1 колонка на телефоне,
  2 — на ноутбуке, 3 — на широком экране).
- Карточка: название и одна строка «что делает»; «Модель» — первая строка «по умолчанию»
  (модель реестра, «как у агента …» или «не выбрана»), «Не использовать» — только у агентов
  с моделью по умолчанию (Планировщик), дальше модели из каталога по фильтру агента; под
  списком — итоговая модель и её доступность (подписка — «ключи Broker не тратятся»);
  «Ключи» — переключатель Авто / Платный / Бесплатный, у стандартного пометка «станд.»;
  max_tokens — где он есть (пусто — по умолчанию); «Промт» — сворачиваемый редактор со
  стандартным текстом, подсказкой подстановок и «Сбросить к стандартному»; правила в коде
  (формат ответа, правила звонка) — свернутые, только чтение. У Охранника в карточке —
  «Запреты» (`guard_rules`).
- У Внимания в карточке — компактный блок «Как она отвечает» (`attention-block.tsx`, логика —
  `attention-logic.ts`, [attention.md](attention.md)): три режима кнопками («Как живой
  человек», «Только когда свободна», «Всегда сразу») с одной строкой подсказки выбранного;
  ползунок «Темп» 0.5–2 с подписями «быстро — обычно — неторопливо» и значением («обычно
  ×1.0»); три переключателя «Может оставить прочитанным», «Писать после пропущенного звонка»,
  «Ночью «не беспокоить»». В «Всегда сразу» темп и переключатели неактивны. Блок — часть
  общего черновика: сохраняется той же кнопкой «Сохранить агентов».
- «Всё по умолчанию» (иконка на карточке) спрашивает подтверждение и сразу сбрасывает агента
  на сервере (у Внимания — и его блок); несохранённые правки других агентов остаются.

### Фильтр моделей

`features/persona/model-filter.ts`: модель подходит агенту, если у неё есть все модальности и
возможности хотя бы одного варианта из `model_filter` агента (`input_modalities`,
`output_modalities`, `capabilities` из `GET /models`). Фильтры агентов — в
[agents.md](agents.md).

Доступные модели идут первыми, у остальных пометка «недоступна» или «доступность
неизвестна». Сохранённое значение остаётся в списке, даже если модель больше не подходит
или пропала из каталога, — сохранение его не потеряет.

### Жизнь

`features/persona/life` ([persona-life.md](persona-life.md)), раздел «Жизнь» на странице
персонажа, вкладки (содержимое вкладок не размонтируется — черновики не теряются):

- **День** — карточки «Сегодня» и «Завтра» (`GET /persona/days`): события с временем, местом,

  `now_minute` от сервера), значок «план модели / изменён вручную / ошибка плана / не
  спланирован». «Спланировать заново» ставит задачу (202) и потом 2 минуты перечитывает дни
  каждые 4 с. «Изменить» — таблица событий с проверкой порядка и наложений до отправки.
  У события не ровное настроение — метка «не в духе: причина»; в правке колонки «Настроение»
  и «Почему» ([persona-life.md](persona-life.md), «Настроение дня»).
  Две карточки стоят рядом, только когда сам раздел шире 64rem (контейнерный запрос, а не
  ширина экрана); карточка в правке занимает всю строку.
- **Мир** — вкладки Распорядок (дни — кнопки пн…вс, время, что, где, с кем, занятость), Люди,
  Увлечения, Места, Облик (маникюр, серьги, украшения и часы, укладка, прочее — одинаковы на
  всех фото), Дом (общее описание квартиры и таблица комнат: как выглядит, расстановка,
  светильники, вид из окна; первая — «по умолчанию»); одна кнопка «Сохранить мир» и «Отменить».
- **Истории** — карточки с названием, статусом, датой конца, сутью и стадией, свои кнопки
  «Сохранить», «Отменить» (пока есть правка) и «Удалить» (с подтверждением); внизу «Добавить
  историю». Когда Планировщик двигает стадию, нетронутая карточка показывает новую, а набранная
  правка остаётся (карточка не пересоздаётся).
- **Канон** — факты с датой и чатом: изменить, отклонить, вернуть.

Таблицы — общий `RowsEditor` (`rows-editor.tsx`). Раскладку выбирает контейнерный запрос
(`@container`) по ширине самой таблицы, а не экрана: `gridMinRem` считает, сколько нужно всем
колонкам (минимумы дорожек, кнопка удаления, зазоры), `gridStep` берёт ближайший шаг
контейнера (32 … 96rem) — от него сетка с заголовком, уже — карточки, поля в которых текут в

нужно ~68rem (на 1920 px — сетка), событиям дня ~76rem (в карточке дня на 1920 px — карточки).
Чистая логика (проверки, текущее событие) — `life-logic.ts`. «Несохранённые изменения» охраняют
мир, истории, правку дня и канона.

## Чаты

- От 1024 px два столбца: список и переписка. Уже — один: открытый чат в адресе
  (`/chats?id=5`), кнопка «назад» возвращает к списку.
- Список: поиск (`SearchInput`), фильтр «Персонаж» (`PersonaFilter`, если персонажей больше
  одного; тогда в каждой строке и имя персонажа, который отвечает), значок мессенджера чата перед
  именем (Telegram, Instagram, WhatsApp — `ChatRow.channel`, `components/channel-icon.tsx`; тот
  же значок в шапке переписки), статус для команды (плашка под именем, см. ниже), непрочитанные,
  «нужен оператор», точка ИИ, превью последнего сообщения и время; подгрузка следующих страниц
  по `before=<last_message_at>`. Поиск и фильтр живут в адресе рядом с открытым чатом
  (`/chats?id=5&q=анна&persona=2`): на телефоне, где список прячется при открытии чата, «назад»
  возвращает к тому же отфильтрованному списку.
- Переписка — лента `GET /chats/{id}/timeline`, старые страницы подгружаются при прокрутке
  вверх по `before_id`. Контейнер `flex-col-reverse`: лента открывается внизу и не прыгает,
  когда сверху дорисовываются старые события.
- Как рисуется событие (`timeline-entry.tsx`, `timeline-logic.ts`): сообщения — пузыри
  (клиент слева, персонаж справа, оператор справа с подписью «оператор»); фото, видео
  (`<video controls>`), голосовое (`<audio controls>` и расшифровка), файл (чип и выжимка);
  звонок — карточка с направлением, длительностью, исходом и расшифровкой; генерация —
  чип со статусом; не доставлено — красным; журнал (проверка заблокировала, нужен оператор,
  ИИ включён/выключен, заметка, память обновлена, её решение на проверке телефона —
  «Марина: прочитала, ответит позже в 20:40 (после рынка)», запланированный контакт —
  «Запланировано менеджером: позвонить — «тема»» или «Она решила написать: «тема»») — мелкой
  серой строкой по центру; `media_understood` отдельно не показывается. Звонок — «Входящий
  звонок» или «Исходящий звонок» по `direction`; если есть `recording_url` — «Запись разговора ·
  1:34» и `<audio controls preload="none">` с этим адресом (как файлы медиа: та же cookie-сессия,
  перемотка через Range).
- В шапке переписки — переключатели «Отвечать сразу» (этот чат без пауз Внимания, для
  проверки), «Без отказов» (этому собеседнику она не отказывает, [writing.md](writing.md)),
  «Звонит сама» (может сама позвонить в этом чате, [calls.md](calls.md)) — один компонент
  `chat-flag-switch.tsx` — и «ИИ в чате».
- «Запланировать» в шапке (`contacts-sheet.tsx`, логика — `contacts-logic.ts`) открывает
  боковую панель «Запланировано»: форма «Сообщение / Звонок», «Когда» — по умолчанию «Сейчас»
  (уходит момент нажатия, а не открытия формы), кнопки «Через 15 мин», «Через час», «Вечером в
  19:00», «Завтра в 10:00» и отдельные поля даты и времени для остального, под ними — «Отправится
  22.11 в 19:05»; уходит ISO-строкой со смещением браузера), «О чём написать / о чём звонок» (до
  500 символов) и «Запланировать»; тема и время (не раньше минуты назад) проверяются до запроса, ошибки сервера («Время уже прошло», «Звонки выключены у персоны») —
  общим тостом. Ниже — план чата (новые сверху): значок вида, время, тема, статус
  («Запланировано», «Выполняется», «Готово», «Не вышло», «Отменено»), результат, пометка «сама»
  у того, что она решила сама, и «Отменить» у запланированного. После создания и отмены
  перечитываются план (`qk.contacts`) и лента. Переключатели, которые сохраняются
  сразу (эти, ИИ клиента в лидах, «референс» в медиатеке), — один `MutationSwitch`: пока
  запрос идёт, показывает новое значение и неактивен. После своих действий шапка перечитывает
  чат одной функцией `invalidateChat` (`features/chats/api.ts`).
- На телефоне (уже 640 px) в шапке остаются имя, «Паспорт», «Запланировать» (значок) и «ИИ в
  чате»; «Заметка», «Отвечать сразу», «Без отказов», «Звонит сама» и «Оператор разобрался»
  уходят в меню «⋮» (точка на нём, пока нужен оператор).
- «Почему так» у ответа персонажа с `reply_run_id` открывает боковую панель из
  `GET /reply-runs/{id}`: блоки контекста в том порядке, в каком их читает модель (распорядок,
  истории, канон, карточка клиента, давняя переписка, итоги недель и дней, лента за сегодня,
  заметки дня, факты, точные данные на сейчас, каталог медиа, «Вспомнила»), отдельным списком
  — «Дни в контексте» (какие итоги дней видела модель), план, вердикты проверки и каждый
  вызов модели (модель, токены, стоимость, время, запрос и ответ).
- Открытый чат с непрочитанными отмечается прочитанным (`POST /chats/{id}/read`).

### Статус для команды

«Статус Марины» ([attention.md](attention.md), «Статус для команды»): что она делает с этим
чатом сейчас и почему ответа ещё нет. Видно только команде — клиенту и агентам не уходит.
Компоненты — `features/chats/persona-status.tsx`, логика — `persona-status-logic.ts`.

- В строке списка — цветная плашка под именем клиента (`PersonaStatusPill`): точка, `title` и
  после него `· detail` в одну строку с обрезкой — причина видна и на телефоне, и с клавиатуры,
  и программе чтения с экрана; во всплывающей подсказке (мышь) — `title — detail` целиком и
  «Видно только команде». Цвет по `tone`: `ok` зелёный, `wait` основной (синий), `busy` бирюзовый, `warn`
  жёлтый (как «нужен оператор»), `off` серый. Цвет зависит только от `tone`, не от `code` и не
  от текста: «Пишет ответ» (`thinking`, `ok`) зелёная, «Пишет ответ — дольше обычного» (тот же
  `thinking`, `warn`) жёлтая; «Записывает кружок» с `detail` «генерация идёт 1 мин 20 с · обычно
  2–6 мин» — как пришло с сервера. Фронт не знает текстов статусов.
- Под шапкой переписки — полоса на всю ширину (`PersonaStatusStrip`, `role="status"`):
  `title` жирным, рядом «до 20:40 по её времени · через 12 мин» (если пауза кончается в
  известное время), ниже `detail`; справа значок «только команде» с подсказкой (на телефоне —
  только значок).
- Обновление: полоса читает `GET /chats/{id}/status` (`qk.chatStatus`) — на любое живое
  событие этого чата и каждые 30 с; список чатов перечитывается каждые 30 с и на события,
  меняющие строку; «через N мин» пересчитывается раз в 30 с (`hooks/use-now.ts`).

## Живые обновления

`AppShell` один раз открывает `EventSource('/api/events')`. Каждое событие
`{chat_id, event_id, kind}` превращается в набор ключей (`invalidationsFor` в
`lib/events.ts`), и TanStack Query перечитывает только их:

| Событие | Что перечитывается |
|---|---|
| любое | лента этого чата `qk.timeline(chat_id)` и его статус для команды `qk.chatStatus(chat_id)` |
| `message_in` | + списки чатов, шапка этого чата, клиенты |
| `message_out`, `message_edited`, `message_deleted`, `send_failed`, `call`, `guard_blocked`, `operator_needed`, `attention`, `generation_*` | + списки чатов, шапка этого чата |
| `ai_toggled` | + списки чатов, шапка этого чата, клиенты |
| `client_updated` | + шапка этого чата (в ней паспорт клиента), клиенты |
| `memory_updated` | + шапка этого чата, клиенты, «Дни» этого чата `qk.chatDays(chat_id)` |
| `media_understood`, `operator_note` | только лента и статус |
| `initiative` | + план контактов этого чата `qk.contacts(chat_id)` |

`message_out`, `send_failed` и `call` тоже перечитывают план контактов (запланированное
сообщение ушло, звонок состоялся).

После обрыва браузер переподключается сам. События, пришедшие во время обрыва, потеряны
(поток без id, догнать нечем), поэтому каждое открытие потока после первого (`onopen`)
перечитывает всё, что событие могло изменить: `qk.chats` (списки чатов, шапка и статус
открытого чата), `qk.timelines`, `qk.clients`, `qk.allChatDays`
(`RECONNECT_INVALIDATIONS`). Это префиксы: заново грузится только то, что на экране. Свои
действия (отправка, переключатели, заметки) тоже инвалидируют нужные ключи сразу, не
дожидаясь события.

## Кружок в ленте

Кружок (`message.kind = video_note`) показывается кругом, как в Telegram: без кнопок плеера и полосы
перемотки (`RoundVideo` в `features/chats/media-view.tsx`). Клик — играет со звуком, ещё клик —
пауза; тонкое кольцо по краю показывает прогресс, внизу длительность. Обычное видео остаётся с
кнопками.

## Стикер в ленте

Стикер (`message.kind = sticker`, `text` — его эмодзи) показывается эмодзи и маленькой подписью
«стикер» (`StickerLine` в `features/chats/timeline-entry.tsx`). Её стикер приходит без файла —
эмодзи крупно (`text-4xl`), пустого пузыря не бывает; у входящего с файлом картинка остаётся
(`MediaView`), эмодзи под ней поменьше. В списке чатов — «Стикер · 😘».
