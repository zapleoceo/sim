# Персонажи: несколько персонажей, клонирование, канал Telegram

Код: `backend/sim/services/persona_clone.py`, `sim/telegram/login.py`, `sim/telegram/client.py`
(`ChannelRuntime`), API — `sim/api/routes/persona.py`, `routes/channels.py`, дашборд —
`frontend/src/features/persona/*`. Контракт — [api.md](api.md), таблицы — [database.md](database.md).

## 1. Сколько угодно персонажей

- Каждая строка, которая принадлежит персонажу, несёт `persona_id`: канал, клиент, чат,
  медиатека, жизнь (истории, дни, канон), генерации.
- **Кто отвечает в чате.** Чат принадлежит персонажу своего канала (`chat.persona_id =
  channel.persona_id`, его ставит `Inbox.resolve_chat`). Ответ, проверка, звонок, распознавание,
  генерация, паспорт берут персонажа ЧАТА — никогда «первого персонажа». Одно правило для
  входящих, ответов и звонков — `ai_allowed(persona, client, chat)` в
  `sim/services/turn_state.py`: это персонаж этого чата, он активен, ИИ включён у персонажа,
  клиента и чата.
- **Клиент** принадлежит персонажу канала, куда он написал впервые (`client.persona_id`). Если
  тот же человек напишет на аккаунт другого персонажа, клиент остаётся одним (личность
  Telegram одна — `client_identity`), но появляется второй чат, и в нём отвечает второй
  персонаж. Паспорт у клиента один ([leads.md](leads.md)).
- **Access hash.** Telegram выдаёт каждому аккаунту свой `access_hash` собеседника, поэтому он
  хранится в чате (`chat.peer_access_hash`, его обновляет `Inbox`), а отправка берёт его оттуда.
- **Фоновые задачи** работают со всеми персонажами одинаково: `life_tick` планирует дни каждого
  активного персонажа с моделью «Жизнь», ход ответа и паспорт идут по `chat_id`, процесс
  `telegram` держит по клиенту Telethon на каждый канал.

### Архив вместо удаления (`persona.is_active`)

`PATCH /api/personas/{id}` `{is_active: false}` — персонаж в архиве: никому не отвечает (входящие
сохраняются), не берёт звонки, дни не планируются, его аккаунты Telegram процесс `telegram`
отключает при следующем обновлении (до 60 с). Ничего не удаляется; `{is_active: true}`
возвращает всё как было. В списке «Персонажи» архивные — внизу с пометкой «в архиве».

## 2. «Клонировать»

Новый персонаж делается из существующего: имя + галочки, что скопировать. Одна функция
`clone_persona(session, storage, source_id, name, parts) -> Persona`; части — перечисление
`ClonePart` (`sim/domain/enums.py`), на каждую часть один копировщик в `COPIERS`. Новая часть —
новое значение перечисления и одна строка в `COPIERS`, остальное не меняется.

| Часть | Что копируется | По умолчанию |
|---|---|---|
| Основное (`basics`) | пол, язык, часовой пояс, дата рождения | да |
| Промт (`prompt`) | промт | да |
| Модели (`models`) | все `model_*`, в том числе «Жизнь» и «Паспорт клиента» | да |
| Голос и фон (`voice`) | голос, манера речи, фон в голосовых | да |
| Правила проверки (`guard`) | `guard_rules` | да |
| Внешность (`appearance`) | описание внешности | да |
| Мир (`world`) | распорядок, люди, увлечения, места (`life`, глубокая копия) | да |
| Истории (`arcs`) | истории со стадией и статусом | да |
| Медиатека (`media`) | фото и видео медиатеки с подписями, тегами и флажком «референс»; **файлы копируются под новыми ключами** (удаление у копии не трогает оригинал); аватар — если он из медиатеки | да |
| Переключатели (`switches`) | ИИ, голосовые, фото, видео, звонки, пауза перед ответом | да |
| Канон (`canon`) | активные факты о себе (без ссылки на чат) | **нет** |

**Никогда не копируются:** каналы, клиенты и чаты, спланированные дни, сгенерированные медиа,
генерации, ходы ответа. У клона нет канала — он никому не отвечает, пока ему не подключат
Telegram.

Порядок частей фиксирован (порядок `ClonePart`), имя уникально (400 «Персонаж с таким именем уже
есть»). Всё идёт в одной транзакции запроса; если что-то упало, уже скопированные файлы
удаляются, а откат транзакции убирает строки.

## 3. Канал: подключить Telegram из дашборда

Персонаж → «Канал» → «Подключить Telegram» (или «Подключить заново»). Вход по QR-коду, без SMS.

```
api_id + api_hash (+ прокси)          POST /personas/{id}/channels/telegram/login
  → канал персонажа (создаётся при первом входе, статус new)
  → Telethon: connect → qr_login()    → {state: qr, qr: SVG}
дашборд каждые 2 с                    GET  /personas/{id}/channels/{cid}/login
  → ещё не отсканирован                → qr (через ~30 с новый QR: старый истёк → recreate)
  → у аккаунта облачный пароль         → password
пароль 2FA                            POST /personas/{id}/channels/{cid}/login/password
  → неверный                           → password + «Неверный пароль…»
  → вошли                              → connected
```

- **Где живёт вход.** В процессе `api` (`TelegramLogins`): по одному незаконченному входу на
  канал, клиент Telethon только в памяти. Вход, который бросили, закрывается через 10 минут
  (`LOGIN_TTL_S`); после перезапуска `api` вход нужно начать заново (`state: none`).
- **Успех.** `channel.credentials_enc` = Fernet-JSON `{api_id, api_hash, session, proxy}`
  (`sim.crypto.encrypt_json`, ключ `SIM_SECRET_KEY`), статус `connected`, `account_id`,
  `account_label` (`@username` или телефон), ошибка очищена. Процесс `telegram` подхватывает
  канал при следующем обновлении (`ChannelRuntime.start`, раз в 60 с).
- **Один аккаунт — один персонаж.** Если этот аккаунт уже работает у другого персонажа (тот же
  `account_id` на не выключенном канале), вход заканчивается ошибкой и ничего не сохраняется.
- **«Отключить»** — `POST /personas/{id}/channels/{cid}/disable`: статус `disabled`, процесс
  `telegram` отпускает аккаунт при следующем обновлении. Сессия остаётся сохранённой; вернуть —
  войти заново.
- **Секреты.** api_hash, сессия, токен QR и пароль никогда не пишутся в лог и не возвращаются
  API: ответы шага — только `{channel, login: {state, message, qr}}`.
- **Ошибки** — по имени класса Telethon: неверная пара api_id/api_hash, FloodWait («Telegram
  просит подождать N с»), неверный пароль (шаг пароля остаётся), прочее — «Не удалось войти
  (Имя)». Неверный прокси проверяется до подключения.

### Как процесс `telegram` видит каналы (`ChannelRuntime.start`)

Каждые 60 с: все каналы `telegram_user` активных персонажей, у которых есть учётные данные и
статус не `disabled`.

- новый или заново подключённый канал → запускается;
- канал выключили, у персонажа архив, учётные данные пропали → его клиент останавливается;
- учётные данные сменились (вошли заново, может быть, другим аккаунтом) → клиент
  перезапускается с новыми;
- канал в `error` после мёртвой сессии не перезапускается, пока вход не вернёт его в
  `connected`.

## 4. Дашборд

- **Персонажи** (`/personas`) — таблица на всю ширину: персонаж (аватар, имя, «в архиве»),
  канал (аккаунт и статус), число лидов (ссылка на «Лиды» с фильтром), ИИ отвечает или нет,
  «Клонировать».
- **Страница персонажа** (`/personas/$id`) — всё, что было на странице «Персонаж»: основное,
  промт, внешность, модели, голос, проверка, переключатели, жизнь, правила формата, канал,
  медиатека; в шапке «Клонировать» и «В архив» / «Вернуть из архива».
- Диалог «Клонировать»: имя и галочки частей с подсказками; канон выключен; после создания —
  переход на страницу нового персонажа.
