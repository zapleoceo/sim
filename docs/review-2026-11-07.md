# Риски и дальнейшие шаги SIM

Ниже результаты статического ревью commit b27a89b. Они не являются отчётом об инцидентах production и не заменяют воспроизведение тестами. P1 означает устранить до признания соответствующего сценария готовым, P2 означает исправить в ближайшей итерации.

## P1 Публикации Instagram
ContentService при publisher=None сохраняет failed, стандартный Container не подключает publisher. Есть adapter publish_photo, но сквозной путь незавершён.
Действие: реализовать и проверить связку либо ясно обозначить недоступность публикации в UI.
[Источник](https://github.com/zapleoceo/sim/blob/b27a89ba5c7dae31ed48da78d2eefef6db681100/backend/sim/services/content.py#L113-L127), [wiring](https://github.com/zapleoceo/sim/blob/b27a89ba5c7dae31ed48da78d2eefef6db681100/backend/sim/wiring.py#L146-L165).

## P1 Задержки очереди
Worker.tick ждёт gather всей пачки, новые SEND jobs и запуск новых polling sweeps ожидают медленный LLM.
Действие: разнести scheduling/polling и обработку ограниченным пулом; тест с одним зависшим reply и готовым send.
[Источник](https://github.com/zapleoceo/sim/blob/b27a89ba5c7dae31ed48da78d2eefef6db681100/backend/sim/worker/loop.py#L47-L56), [главный цикл](https://github.com/zapleoceo/sim/blob/b27a89ba5c7dae31ed48da78d2eefef6db681100/backend/sim/worker/loop.py#L160-L166).

## P1 Повтор оплаты при CSV
Без external_id и occurred_at ID создаётся с текущим временем. Повтор того же файла создаёт новую оплату.
Действие: обязательный устойчивый ID либо документированная детерминированная схема, regression повторного импорта.
[Источник](https://github.com/zapleoceo/sim/blob/b27a89ba5c7dae31ed48da78d2eefef6db681100/backend/sim/services/partner.py#L131-L174).

## P1 Участок Cloudflare к origin
Репозиторный nginx-config описывает Flexible и listen 80. Если production соответствует ему, origin-соединение не защищено TLS. Фактическая инфраструктура не проверена.
Действие: разрешённая проверка origin TLS/firewall, затем согласованный переход на защищённую схему.
[Источник](https://github.com/zapleoceo/sim/blob/b27a89ba5c7dae31ed48da78d2eefef6db681100/infra/nginx-sim.conf#L1-L8).

## P2 История неотправленных сообщений
History filter исключает только guard-blocked, а recent возвращает все delivery-статусы. Failed/cancelled/queued исходящие могут восприниматься моделью как увиденные клиентом. Аналитика обмена тоже не фильтрует delivery.
Действие: определить видимость истории и метрик через фактическую доставку; покрыть отмены и retry.
[Источник](https://github.com/zapleoceo/sim/blob/b27a89ba5c7dae31ed48da78d2eefef6db681100/backend/sim/services/conversation.py#L108-L121), [аналитика](https://github.com/zapleoceo/sim/blob/b27a89ba5c7dae31ed48da78d2eefef6db681100/backend/sim/services/analytics.py#L119-L131).

## P2 Независимость guard
Fallback не проверяется повторно на совпадение с моделью генератора.
Действие: явная политика на повторное совпадение/отсутствующий model ID, соответствующий regression.
[Источник](https://github.com/zapleoceo/sim/blob/b27a89ba5c7dae31ed48da78d2eefef6db681100/backend/sim/services/guard.py#L182-L198).

## P2 Смешение валют
Revenue и payout суммируются без группировки по currency.
Действие: выбрать одну валидируемую валюту либо выводить суммы по валютам; не складывать USD и UAH.
[Источник](https://github.com/zapleoceo/sim/blob/b27a89ba5c7dae31ed48da78d2eefef6db681100/backend/sim/services/analytics.py#L97-L98).

## P2 Устаревший rate-limit route
Усиленный nginx limit относится к /api/auth/login вместо реальных Telegram/link endpoints. Application limiter есть, поэтому защита не отсутствует полностью.
Действие: актуализировать маршруты и проверить реальные ограничения.
[Источник](https://github.com/zapleoceo/sim/blob/b27a89ba5c7dae31ed48da78d2eefef6db681100/infra/nginx-sim.conf#L37-L42).

## Дополнительные сценарии проверки
- Сбой commit после успешной внешней отправки и сетевой timeout с неизвестным исходом: риск дублей при retry.
- Пересланный ref-код: риск ошибочного объединения разных людей между каналами одной персоны.
- Повторная доставка webhook, параллельное создание первого диалога, recovery после lease expiration.
- Длительные jobs и доступность DB pool.
- Документированный backup/restore и измеренные RPO/RTO: пока не подтверждены.

## Предлагаемый порядок работы
1. Зафиксировать воспроизводимые regression-тесты и исходные результаты полного suite.
2. Исправить финансовую идемпотентность, историю доставки и очередь.
3. Закрыть или явно маркировать отсутствующую Instagram-публикацию.
4. Проверить guard и валютную аналитику.
5. Отдельно проверить инфраструктуру после предоставления разрешённого доступа.
6. Выполнить UX-проверку на соответствие брифу: минималистичность, понятность каналов, статусов, ошибок и настройки персонажей.
7. Обновить документацию фактами тестов, точным release commit и оставшимися ограничениями.
